# 路由实验室 · Routing Lab

中文计算机网络教学仿真，参考五台路由器与六台终端的经典网络图，仅使用 Dijkstra 与链路状态，展示路由表建立、故障重收敛与数据包逐跳转发。无需安装依赖，无需后端。

## 打开

直接打开本目录的 `index.html` 即可运行；页面已包含全部脚本与样式，不需要安装依赖。离线包 `routing-lab-offline.zip` 包含单文件模拟器与使用说明。

## 一次课堂演示

1. **路由建立**：点击“选择轮次”中的第 0、1、2、3 轮可直接切换对应状态，最后一轮标注“已收敛”。也可按下一轮顺序播放。初始只知道本机，连直连设备都尚未发现。第一次点击下一轮先发现直连路由器和终端，后续再传播链路通告、使用 Dijkstra 计算路由。观察 R1 到 R3 的距离从未知变为 2，再观察到 R5 的路由。R1–R5 的路由表同时并排显示在拓扑下方，浅绿行表示当前操作改变的记录。自动演示在没有变化的一轮后暂停。
2. **故障与重收敛**：进入 02 即为已收敛的第 0 轮（故障前），不需要再从零建表。选择“关闭 R2”或“R1–R2 延迟增大”两个示例。R2 不连接终端，故障后不会把 H4、H5 的网关关闭；第二个示例保持全部设备在线，将 R1–R2 的代价由 1 增到 8，并用橙色标出变慢链路。故障或延迟变化记为第 1 轮：此时相邻路由器先更新受影响的直连代价（R2 离线变为 ∞，延迟增大变为 8），其余路由暂时保留；第 2 轮才重新计算绕行路径，随后逐轮传播直到重新收敛；第 0 轮始终保留健康稳定的路由，供前后比较。“重新演示”返回故障前。相邻设备一旦获知 R2 离线，后续各轮到 R2 都保持 ∞，不能通过旧链路把它重新算为可达。远端收到故障信息后也将 R2 记为不可达。选择后续轮次观察改道：R1 到 H6 的下一跳从 R2 改为 R4，代价从 3 改为 5，全部六台终端仍可访问。再次点击按钮可恢复设备或正常代价。延迟变化通过路由代价模拟，不按真实毫秒计时。
3. **数据包转发**：选择 H1 → H6。取消自动转发后逐跳点击，查看蓝色轨迹、目的 IP 与 TTL。正常路径为 H1 → R1 → R2 → R3 → R5 → H6；R2 故障或 R1–R2 变慢且收敛后为 H1 → R1 → R4 → R5 → H6。未收敛时发送可能因旧路由而丢包。
4. 路由表只分为“终端 H”和“路由器 R”：上半部分 H1–H6，下半部分 R1–R5，包含目的地、下一跳、代价和状态，目的地只显示 H/R 编号，不显示 IP 或网段。H 行使用所属网关的路径，不额外增加主机通告。点击任意表中的 H/R 行，可预览从该表所属路由器出发的路径。五张表固定按 R1–R5 横向排列，无需切换；各表同一目的地的行保持对齐。桌面同时对比五张表，窄屏在表格区域左右滑动。变化行仍高亮，悬停代价值可查看变化前后的代价及下一跳。表头电源按钮控制对应设备；点击拓扑中的链路可以断开、恢复或修改代价（1–9）。
5. 页面只展示拓扑、路由表和轮次选择，不显示传播记录、本轮观察或控制报文。轮次切换会同步恢复拓扑及路由表，并清除当前数据包；故障或代价变化会重新生成后续轮次。

图中实线及代价是为教学补全的示例，不宣称精确复原附件中不可见的连线。R2 没有画出终端，其 /24 网络作为逻辑接入网络。终端 H1/H2 在 R1 的 LAN；H3 在 R4；H4/H5 在 R3；H6 在 R5。同一 LAN 内的终端直接交付，不经过路由器，TTL 不变；图中省略了局域网交换机，关闭网关不代表 LAN 本身故障。

## 控制与状态

- 01 的初始路由表只知道本机（代价 0），其余路由器和全部终端均为未发现（∞）；第一轮发现直连，随后逐轮传播；“从初始建表”可重新观察学习过程。02 将直连代价更新与重新计算路径拆成两轮，远端还须等待后续信息传播。
- 下一轮：同步交换一组控制报文并更新各表。自动演示与手动按钮使用同一个模型。
- 回退：切换到前一轮并清除当前数据包。各轮保存完整状态，支持任意顺序查看。
- 工具栏重建按钮：01 中保留拓扑、清空学到的路由；02 中显示“回到故障前”，恢复健康稳定的第 0 轮。右上角重置实验：恢复默认设备、连线、代价和终端选择。
- 01 和 02 各自保存进度；02 从已收敛的健康网络开始。切换到 03 使用当前所选轮次的路由。
- 本实验只保留 Dijkstra，不提供算法切换。切换实验环节暂停路由播放。数据包离开转发环节时暂停；返回时若自动转发勾选则继续。
- 数据包与路由控制可以独立推进；已创建的数据包保留原始源/目的地址，修改下拉框影响下一个数据包。
- 键盘：右箭头下一轮，左箭头回退，空格播放/暂停（输入框或按钮聚焦时使用控件自身按键）；标签页用左右箭头切换。

## 算法与适用范围

这是**链路状态与 Dijkstra 的教学模型，不是完整 OSPF 协议栈，也不发出真实网络流量**。

每个本地拓扑变化产生递增序号的 LSA，各节点逐轮交换上一轮已知的数据库，在自己的数据库上执行 Dijkstra：以本机为起点，每次选出距离最小的未确定节点，再更新其邻居距离，最终从最短路径树得到下一跳。链路代价范围为 1–9，不可达使用无穷大，没有 16 的上限。直连发现阶段是教学抽象，不实现完整 ARP 或 OSPF Hello 握手。省略 OSPF 邻居握手、区域、LSA 老化、可靠泛洪的确认和重传、DR/BDR 与等价多路径。本教学模型在本地通告中携带对本机和相邻设备的在线/离线观测，以通告序号判断观测的新旧。每台设备只用自己已收到的观测排除已知离线节点，避免旧的入链路把离线设备重新算为可达或用作中转；恢复后，更新的在线观测解除该限制。远端在收到新通告之前可暂存旧表。这是针对明确设备故障事件的教学抽象，不是完整 OSPF 故障检测实现。

02 的第 1 轮先标记直连故障（代价变为 ∞）或新的链路代价，其余路由暂不改道；第 2 轮才重新计算路径。教学轮次不代表真实秒数。本地网络的路由代价记为 0，图中仅累计路由器之间的链路代价。每个路由器转发前检查 TTL 并减 1，数据包根据该节点当前表选下一跳；无路由、设备离线、下一跳链路失效或 TTL 耗尽时丢弃。终端到网关的 LAN 开销不计入路由代价，不展开 ARP、二层帧和物理波形。

协议依据（2026-10-30 检索）：

- [RFC 2328 · OSPF Version 2](https://www.rfc-editor.org/rfc/rfc2328.html)：链路状态数据库、通告泛洪和最短路径计算。

## 验证与构建

`node --test model.test.cjs` 运行独立模型验收。涵盖 Dijkstra 的初始知识边界、最短路径收敛、远端故障延迟、设备/链路恢复、隔离、代价变化、历史恢复、重启后重新发现直连、发现前拓扑调整不会偷学路径、任意轮次选择、故障前已收敛的第 0 轮、故障/恢复事件追加而不覆盖基线、故障轮更新直连代价但保留其余路由与数据库、下一轮才计算绕行路径、无效事件回滚、故障获知后各轮持续不可达及恢复、故障后重算未来轮次、R2 离线及链路延迟增大后全部终端仍可互通、LSA 序号传播、当前表逐跳转发、终端行与网段路由的一致性、同子网直接交付与 TTL。
