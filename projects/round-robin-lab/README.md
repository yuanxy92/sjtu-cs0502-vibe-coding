# CPU 时间片轮转模拟器

配合《计算机科学导论》软件工程一讲使用，将前一讲的 RR 调度例题转化为可交互的课堂演示。

## 打开方式

直接双击本目录的 `index.html`，使用浏览器打开。无需安装、启动服务器、登录或联网。HTML 已包含全部样式、调度逻辑和交互代码；将该文件单独复制到其他电脑也可以运行。

完整的需求文档保存在 [需求说明.md](需求说明.md)，包含目标、输入、REQ-01 至 REQ-09 调度规则、界面操作、展示要求和全部验收场景。把该文档单独交给 AI，可以用于课堂上的“需求文档生成应用”演示。

## 课堂操作

1. 默认打开课件例题：A–E 的到达时间为 0、2、4、6、8，运行时间为 3、6、4、5、2，时间片为 1。
2. 点击“下一步”，每次推进一个模拟时间单位。CPU、就绪队列、状态表、时间轴和事件日志同步更新。
3. 点击“自动播放”连续演示；每一步按实际事件依次演示完成退出、新到达入队、轮转回队、队首进入 CPU，动画结束后再等待所选播放间隔。“播放间隔”越小播放越快，不影响调度结果。“暂停”会让当前一步的动画完成后停住，之后可继续单步。
4. 点击“重置”清空运行历史并保留参数。此后可编辑进程名称、到达时间、运行时间、时间片，也可添加或删除进程。
5. 点击“恢复课件例题”恢复默认输入。所有进程完成后，播放自动停止。

大屏投影建议使用浏览器全屏。时间轴较长时可左右滚动；事件日志可折叠。窄屏会改为上下排列。

## 观察口径

- 初始时刻为 0：先让已到达进程入队并完成调度，尚未消耗运行时间。
- 时刻 t 的 CPU 面板表示接下来在区间 `[t,t+1)` 运行的进程；时间轴只记录已经执行的区间。
- CPU 中的进程已经离开就绪队列；队列只保留等待 CPU 的进程。时间片耗尽且未完成时回到队尾，完成时退出。
- CPU 和队列中的进程使用同一种实色卡片，仅显示名称和剩余运行时间；卡片中不再重复显示时间片剩余值，时间片参数保留在页面顶部和设置区。
- 上方“新进程”区域显示尚未到达的进程和到达时刻；进程到达时会先亮起、放大，再向下飞入队尾。上方“已完成”区域保留已经完成的进程和完成时刻。
- 边界调度会分成四种卡片动画：CPU → 已完成区域、新进程区域 → 队尾、CPU → 队尾、队首 → CPU。“边界调度中”的各动画属于同一个模拟时刻，不额外消耗 CPU 时间。最后一个进程也会播完退出动画后再停止。
- 同一时刻依次处理：上一单位执行的完成结果、新到达进程入队、时间片耗尽且未完成的进程回队、CPU 空闲时取队首。原队列顺序不变。
- 新到达进程不会抢占尚未用完时间片的运行进程。
- 这是单 CPU、无 I/O 阻塞、不计切换开销的教学模型。
- 动画期间“下一步”和“自动播放”暂时禁用，防止重复推进；“重置”始终可用，并立即取消动画。系统启用“减少动态效果”时跳过位移动画。

## 建议演示顺序

- **复现课件**：运行默认例题，时刻 20 完成，执行顺序为 `A A B A B C B D C B E D C B E D C B D D`。
- **检查同刻事件**：A `(到达 0，运行 2)`、B `(到达 1，运行 1)`，q=1，执行顺序为 `A B A`。
- **观察入队动画**：上述同刻事件的第一步会依次显示 `B 入队 → A 回队 → B 进入 CPU`。使用默认课件例题时，t=2、4、6、8 也适合观察新到达与轮转的关系。
- **观察完成退出**：默认例题的 t=4，A 从 CPU 移入上方“已完成”区域；随后 C 从上方进入队尾、B 从队首进入 CPU。最后在 t=20，D 完成退出后结束播放。
- **修改时间片**：A `(0,3)`、B `(1,1)`，q=2，执行顺序为 `A A B A`。在 t=1 暂停，观察 B 已到达但 A 仍在运行。
- **观察空闲**：只保留 A `(2,1)`，前两个单位 CPU 空闲，t=3 完成。
- **验收输入**：尝试空名称、重名、空时间、负数或小数，确认页面提示并阻止运行。

## 扩展：轮转之后，为什么结果错了？

打开 [race-examples.html](race-examples.html)，或从模拟器底部进入。独立 HTML 可直接双击、离线使用。

投影字号：正文、按钮和代码为 24px，辅助文字不小于 22px，标题和共享数值同步放大；窄屏通过换行和纵向排列保持字号。

页面提供三个例子：计数器少加一次、最后一张票卖了两次、转账读到中间状态。可单步、回退、自动播放、点击时间线，切换无锁 / 加锁保护，并对比 q=1–4 的运行结果。q 表示每轮教学指令数，播放间隔独立控制演示快慢；改变例子、方案或 q 会重置并停止旧播放。

q=1 无锁时，分别得到计数器 1（应为 2）、两人购票成功（只有一张票）、观察者读到 150 元（应为 200 元）。加锁保护完整操作后，四种时间片下均正确。加锁采用获取失败后阻塞、释放后唤醒重试的模型，读写双方使用同一把锁。

这些是扩展示例，尚未核对课件 PDF 原例。更大的时间片可能碰巧避开错误，不能替代同步。转账例子将读取总额简化为一次快照读取，错误读数保留到演示结束。

逻辑检查：`node --test tests/races.test.cjs`。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `index.html` | 可独立复制、直接打开的完整模拟器 |
| `需求说明.md` | 对话中已确认的完整需求文档 |
| `tests/engine.test.cjs` | 直接加载 HTML 内同一份调度引擎的 20 项自动检查，包含完成退出、动画事件顺序和中间队列 |

如需重新检查调度逻辑，在安装了 Node.js 的环境中执行：

```sh
node --test tests/engine.test.cjs
```

运行模拟器本身不需要 Node.js。
